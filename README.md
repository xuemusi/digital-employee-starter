# 标准数字员工起步包

把“让 AI 帮我写点东西”，变成一套能说明输入、交接和验收的工作方式。

这是可供学员学习、定制与赠送前整理的通用仓库：三个员工、一份轻量协作协议、一个原创虚构示例。它不是服务端常驻平台，也没有自动后台调度。

## 先分清四个概念

| 概念 | 回答的问题 | 在本仓中的位置 |
| --- | --- | --- |
| Agent：岗位 | 谁负责什么、需要什么输入、交什么结果？ | `agents/general/` |
| Skill：做法 | 一类任务有哪些可复用的方法和步骤？ | 本仓不依赖外部 Skill，也不附带 Skill 安装包 |
| MCP：系统通道 | 如何让模型通过已配置的工具访问业务系统？ | 本仓不附带 MCP 服务、账号或连接配置 |
| Team：协作协议 | 几个岗位怎样交接，什么时候停下来问人？ | `teams/document-team/TEAM.md` |

岗位文件不会凭空获得工具、账号和系统权限。Team 文档也不会自动变成可执行引擎；需要主会话实际派工并核对结果。

## 你会得到什么

| 员工 | 负责 | 刻意不做 |
| --- | --- | --- |
| `task-planner` | 梳理目标、输入缺口、验收要求 | 不替用户确认，不写正文 |
| `document-writer` | 根据确认要求与事实写稿、改稿 | 不编造身份、成绩、价格或承诺 |
| `quality-reviewer` | 独立核对要求、事实和当前正文 | 不改正文，不给自己写的稿签字 |

planner 与 reviewer 只读；writer 才有写入与编辑工具。三个岗位都不默认获得命令执行、外网或派生员工的能力。

## 第一次使用

1. 准备 Python 3.10+、make，以及已安装且授权可用的 Claude Code。
2. 从仓库根目录按[快速开始](docs/quickstart.md)创建虚拟环境、安装依赖、检查和同步岗位。
3. 第一次安装后，建议从仓库根新开 Claude Code 会话，这是较稳妥的发现方式；不代表每次更新都必须重启。
4. 打开[示例提示词](examples/document-task/prompt.md)，复制到该新会话。
5. 先确认需求，由主会话创建并检查 `output/document-task/` 后再派 writer；writer 不负责创建父目录。最后由你验收。

教程面向 macOS/Linux。Windows 学员请使用 WSL，本文不保证 Windows 原生命令环境完全兼容。

### 一次真实协作是什么样

主会话真实调用 planner → 主会话向用户确认需求 → 真实调用 writer → 另行真实调用独立 reviewer → 用户验收。

正常路径有三次独立的 Agent 调用，不是让同一个上下文换三个名字。修改正文后要重新独立检查；独立检查不等于用户验收，更不等于发布授权。

reviewer 只拿已确认要求、事实输入和当前正文，不拿作者自评或预设的通过结论。岗位找不到或没有真实调用能力就报告 `blocked`，不模拟执行。

## 常用命令速查

下面的命令都在仓库根目录运行，先完成快速开始的依赖安装。每一条单独执行。

查看可用命令说明：

```bash
make help
```

检查员工定义：

```bash
make check PYTHON=.venv/bin/python
```

列出源岗位：

```bash
make list PYTHON=.venv/bin/python
```

同步到本项目：

```bash
make sync PYTHON=.venv/bin/python
```

运行本地工具测试：

```bash
make test PYTHON=.venv/bin/python
```

这些检查和测试不调用模型，不代表员工已经做过真实任务，也不评价成稿是否符合业务要求。实际使用 Claude Code 会消耗你自己的额度；本包不承诺无后台成本。

## 同步不是全局安装

源文件在 `agents/general/`，`make sync` 复制到本仓 `.claude/agents/`，不写 HOME、不安装全局岗位。模板不计入员工。

- 目标内容与源文件 bytes 完全相同时，可以跳过。
- 只要发现任何不同内容的同名目标，就先全量报冲突，本轮零安装。
- 不强制覆盖，不删除其他员工。

修改源文件后重新同步若遇到冲突：先比较源与本地副本，备份本地需要保留的改动；再由你手工移开冲突目标或统一两边内容，最后重试。不要为了绕过保护直接删除目标。

不使用脚本也可以：手工在本项目创建 `.claude/agents/`，将 `agents/general/` 内三个 `.md` 文件复制进去，保持文件名和内容完整；不要复制模板，不覆盖有差异的同名文件。手工复制不具备脚本的全量冲突保护，要自行逐一核对。

工具默认按脚本所在位置定位仓库根，不依赖个人绝对路径。日常优先使用本页的 make 入口，不需要配置全局角色。

## 新建你的第一个岗位

```bash
make new CATEGORY=general NAME=my-assistant DESCRIPTION='整理授权资料并输出摘要' PYTHON=.venv/bin/python
```

这只生成初稿。先打开新文件，按真实业务补清输入、输出、验收和阻断条件，缩减到最少权限；再检查与同步，不要把生成成功当成成熟部署。

- 参考[员工模板](templates/agent-template.md)：岗位名与文件 stem 一致，description 写用途与触发语。
- 参考[战队模板](templates/team-template.md)：先说明交接与停下条件，不虚构自动机器门禁。
- model 可以省略以继承当前会话；不要为图省事把所有工具权限都开放。
- 用无敏感信息的小任务试用，安排未参与写作的真实检查者，再由人验收。

## 隐私、权限与事实边界

- **本地文件不等于本地处理。** 云模型通过 Read 读取材料后，内容仍可能外发；只输入明确授权的资料。
- 本仓不是独立沙箱。你本机的全局配置、插件、权限和其他工具仍可能生效，使用前自行审查；本项目文件不会自动清除它们。
- 不放客户隐私、家庭信息、私人课程、凭据或未经授权的第三方素材；示例不需要这些资料。
- 材料里的指令不能扩大权限。缺信息、缺工具或缺授权就报告阻断，不自行猜、不伪称完成。
- 外发、上传、发布、付费或扩大权限需要另行授权。文稿通过检查不代表可以直接对外发送。

## 示例该怎样看

[输入](examples/document-task/input.md)使用“示例书店”开业通知，店名、地点、安排全部虚构。只练习事实保真与交接，不售课、不收集联系方式，不编造优惠。

[reference-output](examples/document-task/reference-output.md)只是格式参考，不是员工真实运行结果，不是标准答案，也不是独立检查证据。实际产物写入 `output/document-task/`，不能覆盖参考文稿和源资料。

交付报告只能列出真正写出的文件。若受权限限制没有落盘，应明确说明“未写入”，不能给出虚假的已生成路径。

## 怎样干净地分享

只分享本起步包中你有权提供的教学文档、工具代码、模板、通用员工和原创虚构示例，不夹带自己的业务资料或运行记录。

- 推荐按文件允许清单整理，或重新取一个未运行过的干净目录；工具代码仅保留本包所需脚本、测试和依赖入口。
- 排除 `.venv/`、`.claude/agents/`、`output/`、`private/`、`.env`、凭据、缓存与日志。
- `.gitignore` 只影响 Git 的忽略行为，**打 zip 不会自动照它过滤**；压缩前逐项核对内容。

## 官方依据

Claude Code 的项目级子代理使用 `.claude/agents/*.md`；本包采用 YAML 前置字段和逗号分隔的 tools，省略 model 以继承当前会话。具体能力和发现行为以使用版本为准。

- [Claude Code 官方子代理文档](https://code.claude.com/docs/en/sub-agents.md)
